# 开发说明

## 代码边界

| 目录 | 职责 |
| --- | --- |
| apps/Meno | 托盘、独立窗口路由、宿主偏好、全局快捷键、登录启动、Unix socket 及串行命令入口 |
| apps/MenoMCP | 官方 SDK 的标准 MCP Server；只做参数转换和 IPC，不直接读写业务数据 |
| apps/MenoCLI | 参数解析、JSON 输出、退出码和同一 IPC 客户端 |
| packages/MenoCLIKit | 无副作用的 CLI 参数解析、时间单位转换和可独立测试的命令构造 |
| packages/MenoPluginKit | 模块描述、按需数据／窗口实例、只在启用后创建的运行时，以及宿主隔离启停 |
| packages/MenoControlProtocol | Codable 命令回执、严格 JSON 值、六工具 Schema、私有 Unix socket 和后台启动 |
| plugins/Reminders/RemindersCore | 提醒定义、日历计算、SQLite、迁移、事务、幂等、触发实例和确认／延期 |
| plugins/Reminders/RemindersPlugin | 快速创建、列表与历史、原生通知通道、单定时器运行时、多屏 NSPanel 队列 |

新增子应用时增加本地 package，实现 MenoPlugin（数据服务和窗口）及 PluginRuntime（start/stop），注册 PluginDefinition 并增加业务命令路由。数据服务可在停用时载入，运行时只在启用后创建；窗口关闭不参与运行时生命周期。首版共用进程，不支持任意二进制热加载或崩溃隔离。宿主测试包含第二个模拟模块，验证停用一个模块不会停止另一个。

SwiftPM 宿主构建产物为 `MenoHost`，打包时作为 `Contents/MacOS/Meno`；CLI 构建产物为 `meno`，放在 Helpers 中，避免默认大小写不敏感的文件系统将二者构建目录混为一个。

## 数据与迁移

默认根目录为 `~/Library/Application Support/Meno/`，宿主设置为 preferences.json，提醒数据为 `Plugins/com.meno.reminders/reminders.sqlite`。目录权限 0700、数据库和偏好 0600，SQLite 使用 WAL、FULL 同步及 schema user_version=1。表分别保存 reminders、occurrences、requests 和 metadata，业务写入与幂等记录在 BEGIN IMMEDIATE 事务内提交。出错回滚，不以清空数据库恢复运行。

SQLite 打开时检查版本、quick_check 和可解码数据，较新的 schema 或损坏数据直接报告。旧 reminders.json 会先严格校验、保留原文件，并建立 reminders.json.pre-sqlite.bak，再按原 ID 原子导入；旧事项默认 system，迁移标记防止重复导入。旧宿主 enabledPlugins 偏好只迁移一次到业务 metadata；损坏宿主偏好会保留文件，并拒绝覆盖该配置。

宿主持有实例文件锁，拿到锁后才能清理自身过期 socket。socket 为 0600，客户端与服务端都校验对端 uid，消息包含协议版本、关联 ID、来源和命令，每连接只处理一个请求，限定 1 MiB 和 30 秒 I/O 超时。不开放网络 HTTP 端口。主线程上的业务事务不含 await；跨调用的命令门闩按 FIFO 串行执行，通知授权弹窗的用户等待不占用此门闩。

## 调度和恢复

提醒启用、模块运行和一次触发的状态分开存储。普通触发 ID 由提醒 UUID、定义 revision、原定毫秒时间组成，延期使用独立 ID，保存标题和类型快照。修改或取消定义先撤销旧实例，再按新 revision 建计划；系统通知和全屏只使用各自通道。

运行时只维护最近下一次到期的一个 Timer，在编辑、通知权限更新、应用激活、系统时间／时区变化、屏幕变化和唤醒时重新计算。系统通知只保留最近 60 个一次性请求，较远事项返回容量受阻原因，到期后滚动补入；这个值是首版保守容量策略，不是禁止保存第 61 条事项。重复事项按每次原定墙上钟点续排，不依赖用户确认时间。宿主意外停止时，系统中已提交的一次性通知可能继续送达，但后续重复计划和全屏都依赖宿主继续运行。

系统提交前先持久化意图，已存在的相同请求不重复添加；恢复时核对 pending 和 delivered ID。过去且已有 submitted 记录的通知，即使没有送达记录也不盲目重发，历史注明展示待核实。通知 dismiss 不记为完成，只有“知道了”／明确确认才记 acknowledged；“5 分钟后提醒”把当前实例记为 snoozed，并产生独立实例。

全屏使用不激活 App 的 NSPanel，覆盖 NSScreen.screens 的完整 frame，鼠标所在屏幕展示内容和按钮，其他屏幕只显示蒙层。全部全屏事项共用一个队列，当前实例处理后才展示下一条；orderFrontRegardless 不主动 makeKey 或激活应用。点击内容后可取得键盘焦点，Esc 延后五分钟。系统降低透明度时使用实色背景，首版不使用闪烁或强制桌面切换动效。

正常停用先阻止新回调、移除定时器和观察者、关闭面板，再等待通知串行 drain 收敛；如果 stop 发生在系统 add 的 await 期间，等待它返回后仍清除刚写入的请求，stop 才结束。仅移除 meno.reminders. 前缀，不误删其他模块。正常退出保留启用偏好，但写入 runtime_active=false，取消待触发任务；下次启动只恢复未来计划。意外退出或休眠恢复使用 30 分钟补偿窗口，主动暂停期间到期的已建计划也标记 missed，不补弹。

单次保存绝对时刻；每天、周一至周五保存 hour/minute，按当地时区重新计算。时区／时间变化撤销旧的未来普通实例，延期的绝对时刻保留。夏令时缺失钟点按 nextTime 顺延，重复钟点使用 first，当天只取第一次。锁屏和会话不活跃期间隐藏覆盖层，恢复桌面后再按补偿窗口处理；不覆盖登录、安全界面，不唤醒休眠电脑。

## 构建与测试

`scripts/test.sh` 执行源码检查、四个 package 的测试并编译全部入口；`scripts/build.sh [release|debug]` 构建、生成原生绘制图标、嵌入两个 Helpers、逐个签名、校验并打 zip，同时生成构建身份与 SHA256SUMS。默认 ad-hoc，MENO_SIGN_IDENTITY 可指定本机证书；没有分发公证或自动发布。`scripts/install.sh` 默认安装到 ~/Applications，已有 App 改名保留，不删除用户数据。

`scripts/integration-test.py` 使用独立测试 Bundle ID、私有临时数据及锁定的 Python MCP 客户端，串行执行工具发现、六工具业务流程、断连及并发重试、CLI 生命周期和 SIGTERM 后恢复，测试结束正常退出本轮进程。测试替身只用于 Swift 单元测试中的系统通知与面板边界，真实集成测试使用实际 App、socket 和官方 MCP 客户端。

真实 MCP 测试使用 `scripts/mcp-smoke.py` 和锁定版本的官方 Python 客户端，见接入文档。编译、单元测试、标准协议互操作、操作系统 API 接受请求、实际屏幕展示和最终用户使用是不同证据层；完整环境、证据文件和未验证条件见验收记录。
