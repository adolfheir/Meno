# 发布与维护

## 开发产物

执行 `make test && make build && make integration && make verify`。Release 输出为 dist/Meno.app、Meno.zip、build-info.json、SHA256SUMS；清单记录源码摘要、Git revision 与是否含未提交改动、Xcode/Swift 版本、架构、依赖和三个二进制的 SHA-256。`python3 scripts/verify-app.py` 会再次核对签名、版本、二进制摘要、图标及第三方许可证；解压 ZIP 后也可以把 App 路径传给该脚本验证。

CI 每次 push、PR 或手动触发后，在 macos-26（Apple Silicon）和 macos-26-intel 上使用 Xcode 26.6 执行同一验证链路，保存日志及各架构安装包 14 天。Runner/Xcode 来源见 [GitHub 官方镜像清单](https://github.com/actions/runner-images/tree/main/images/macos)。CI 的 App、系统 API 和进程测试不证明有人看到通知，也不证明不同桌面空间、睡眠、登录启动或旧版系统通过实机验收。没有自动发布 GitHub Release，也没有自动 Merge PR。

默认 ad-hoc 签名适合本机与 CI 验证，CI 不使用个人签名证书。跨 Mac 分发需要开发者自行提供 Developer ID Application 证书，使用安全时间戳签名、Apple 公证及 stapling，并在另一台 Mac 上验证 Gatekeeper；当前构建脚本的 `--timestamp=none` 用于本机开发，不能直接作为完成公证的分发流程。不要把 Apple Development 签名或 CI ZIP 标成已公证的公开安装包。首版不包含自动更新器。

## 安装、备份和恢复

先从当前安装路径执行 `Contents/Helpers/meno quit` 并等待进程退出，再运行 `scripts/install.sh [目标目录]`。默认目标为 ~/Applications；旧 App 保留为 Meno.previous.<时间>.app。脚本不删除数据库或宿主设置，不能用重新安装修复损坏数据。

备份用户数据前先正常退出 Meno，再复制整个 `~/Library/Application Support/Meno`，包括 Plugins 内数据库及可能存在的 WAL/SHM 文件。不要只在运行中复制一个 SQLite 文件。恢复时保留当前目录副本，使用同版本或支持该 schema 的更高版本 App；较旧 App 遇到未来 schema 会拒绝打开，不能通过修改 user_version 强行降级。取消提醒保留历史，不会彻底删除数据库记录。

诊断先运行 `meno diagnostics`、`meno apps status`，区分后台是否运行、单条是否启用、saved 与 armed、通知权限和运行时错误。通知展示仍受系统通知设置、专注模式及锁屏策略影响。全屏提醒超过 30 分钟补偿窗口不补弹；主动暂停期间错过的事项不补弹。记录 SDK/OS 及构建清单，再提交脱敏问题报告，避免上传真实提醒内容和私有路径。

## 手工验收

在有交互桌面的测试机上验证：窗口关闭后台继续；停用后台仍可编辑；通知授权后实际 banner、通知中心、确认与延期；多屏内容只显示一处、蒙层覆盖完整；按钮和 Esc；客户端退出后提醒继续；切换 Spaces、全屏 App、台前调度、显示器插拔；休眠/解锁；登录启动及实际重新登录；浅色、深色、降低透明度、减少动态效果；macOS 14/15 回退与不同硬件。使用虚构测试事项，结束后只取消本轮创建的事项。结果按“源码/自动化、API/进程、可见交互、实机环境”分别记录，无法执行的项目明确保留为待验收。
